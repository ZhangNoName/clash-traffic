## 2. 安装与运行

把安装盘中的应用拖到“应用程序”，推出安装盘后启动。不要直接在 DMG 内运行；应用会提示先安装。

启动时应用注册当前用户 LaunchAgent，启动独立后台记录器，再加载本机 HTTP 服务中的界面。它不修改 Clash Verge 配置，不替换 Clash 内核，不需要外部 TCP 控制端口。

默认连接位置：

```text
Mihomo Unix socket
/tmp/verge/verge-mihomo.sock

Clash Verge 数据目录
~/Library/Application Support/io.github.clash-verge-rev.clash-verge-rev

本机界面/API
http://127.0.0.1:19797
```

菜单“记录服务”提供启动、停止、打开数据文件夹和卸载服务。当前用户登录后 LaunchAgent 自动运行；退出界面不会停止后台采集。菜单栏图标由桌面应用提供，需要打开应用后才出现。关闭窗口会保留图标，⌘Q 会退出应用并移除图标；后台记录器不受影响。

## 3. 文件与权限

| 文件或目录 | 用途 |
| --- | --- |
| `~/Library/Application Support/ClashTraffic/traffic.sqlite3` | 历史、设置、订阅覆盖、运行状态 |
| 同目录 `traffic.sqlite3-wal`、`traffic.sqlite3-shm` | SQLite 临时事务相关文件，运行时可能存在 |
| 同目录 `identity.key` | 生成稳定节点/应用身份的本机密钥 |
| 同目录 `collector.lock` | 防止同一目录重复运行采集器 |
| 同目录 `service.log`、`.1`、`.2` | 每份约 1 MB 的轮转日志 |
| `~/Library/LaunchAgents/local.clash-traffic.collector.plist` | 当前用户登录自启与异常重启配置 |
| `.app/Contents/Resources/service` | 封装后的后台记录器及 Python 运行时 |
| `.app/Contents/Resources/docs` | 离线文档 |

记录器使用当前用户权限，HTTP 只监听回环地址。应用首次创建数据目录时设置用户专用权限；不需要授予管理员权限。不能读取 Clash socket 或配置时会暂停采集并重试。

## 4. 升级

1. 菜单“记录服务 → 停止本次后台记录”。
2. 退出 Clash 流量簿，替换同一安装位置的 `.app`。
3. 再次打开应用，等待“记录中”。

数据目录独立于 `.app`，替换应用会保留历史、身份密钥、映射和清理设置。移动应用位置后重新启动，会更新服务配置里的可执行文件路径。避免同时打开两个不同位置的副本。

0.2.0 沿用现有数据库结构，本次升级无数据迁移。升级造成的采集中断不补算。

## 5. 备份、恢复与卸载

**备份：**先停止后台记录，复制整个 `ClashTraffic` 数据目录到独立备份位置，然后恢复记录。至少保留数据库及 `identity.key`；若还有 WAL/SHM，必须与数据库一起备份，不能只复制正在写入的主数据库。

**恢复：**停止记录并退出应用；先额外备份当前数据；用同一份完整备份替换数据目录内对应文件，保留当前用户读写权限；重新打开应用。不要把不同时间的数据库与 WAL 混合。密钥丢失不妨碍历史查询，但后续身份可能改变。

**卸载：**先从应用菜单选择“卸载后台服务（保留历史）”，再将 `.app` 移到废纸篓。历史目录不会被自动删除。再次打开应用会重新注册服务；若不再使用，不要重新启动应用。

## 6. 故障排查

| 现象 | 检查和处理 |
| --- | --- |
| 采集暂停 | 确认 Clash Verge 和内核运行；确认 socket 文件存在；尝试菜单启动后台记录 |
| 一直为零 | 确认产生的是代理流量；取消应用/节点筛选；新安装不含之前历史 |
| 页面无法加载 | 检查 19797 是否被其他程序占用，查看后台服务和日志 |
| 日期查询报错 | 范围为 1 分钟至 366 天，结束晚于开始；细粒度最多约 400 个时段 |
| 保存失败或请求校验失败 | 刷新界面后重试；后台重启后 CSRF 令牌会更新 |
| 未知订阅 | 在归属管理核对节点并手动指定；动态 Provider 等配置形式可能缺少证据 |
| 磁盘使用稍高于上限 | 等待下一次每分钟维护；容量上限为软上限，日志独立限额 |
| 退出应用仍在采集 | 属于正常行为，使用“停止本次后台记录”停止 |

可在终端运行以下只读诊断。`/api/status` 包含临时 CSRF 令牌，不要直接公开完整响应。

```sh
launchctl print "gui/$(id -u)/local.clash-traffic.collector"
ls -l /tmp/verge/verge-mihomo.sock
lsof -nP -iTCP:19797 -sTCP:LISTEN
tail -n 30 "$HOME/Library/Application Support/ClashTraffic/service.log"
```

状态正常但“采集暂停”时先关注 Clash socket 和配置读取。日志只记录错误类别，不打印订阅凭据或原始连接。

## 7. 从源码运行

以下命令在交付源码目录 `clash-traffic/` 中执行。开发服务使用单独的数据目录和端口，不访问正式历史库。

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python -m clash_traffic.server --data-dir ./work/dev-data --port 19798
```

开发时先按第 10 节安装并构建 Next.js 前端，再打开 `http://127.0.0.1:19799`。前端改动需重新运行 `build_frontend.py`，Python 改动需要重启服务。开发采集器也会读取 Clash，但记录到独立数据库，不合并到正式统计。按 Ctrl+C 退出。

| 启动参数 | 默认值或作用 |
| --- | --- |
| `--data-dir` | 正式数据目录；开发必须显式设为独立目录 |
| `--port` | 19797；建议开发用 19798 |
| `--socket` | `/tmp/verge/verge-mihomo.sock` |
| `--verge-dir` | 上述 Clash Verge Rev 数据目录 |

备用 CLI：`python3 manage.py status/start/stop/restart/open`，每次只传一个命令。这些命令控制正式用户服务，不是开发端口。`manage.py install` 优先安装源码旁的原生 `.app`；缺少原生应用时走旧版 Python/浏览器开发入口。

`manage.py uninstall` 是旧版源码卸载流程，还会移除 `~/Applications` 下的应用入口；日常桌面版请优先使用应用菜单卸载服务。

## 8. 构建与验证

构建需要 macOS arm64、Xcode Command Line Tools 的 clang、Python 3.9 及构建依赖。当前成品用该环境生成。

```sh
python3 -m venv .build-env
.build-env/bin/python -m pip install -r requirements-build.txt
.build-env/bin/python build_docs.py
.build-env/bin/python build_macos.py --work-dir ./work/native-build --output ./release
codesign --verify --deep --strict './release/Clash 流量簿.app'
```

`build_docs.py` 将四份 Markdown 生成对应 HTML 与目录；`build_macos.py` 先构建 Next.js 静态前端，再编译 Cocoa 外壳、打包 Python 服务和静态资源、嵌入文档，并执行本地签名验证。

下面使用新的 staging 目录制作 DMG：

```sh
mkdir -p ./work/dmg-stage
cp -R './release/Clash 流量簿.app' ./work/dmg-stage/
cp -R ./docs ./work/dmg-stage/文档
ln -s /Applications ./work/dmg-stage/Applications
hdiutil create -volname 'Clash 流量簿' -srcfolder ./work/dmg-stage -format UDZO ./release/Clash-Traffic-0.2.0-arm64.dmg
hdiutil verify ./release/Clash-Traffic-0.2.0-arm64.dmg
shasum -a 256 ./release/Clash-Traffic-0.2.0-arm64.dmg
```

发布前检查：40 项 Python 测试、前端测试与 TypeScript 类型检查、日期与分钟回填、清理取消流程、较小窗口中的弹窗标题/底部按钮、原生应用启动、签名与 DMG 校验。真正执行清理的测试只使用临时数据库，不使用用户历史。

## 0.2.0 前端开发与构建

成品仍只需安装 `.app`，不用安装 Node.js。源码开发需 Node.js 20.9+ 与 npm，已用 Node.js 24.17.0 验证。先在项目根目录执行：

```sh
cd frontend
npm ci
npm run test
npm run check
cd ..
python3 build_docs.py
python3 build_frontend.py
python3 -m clash_traffic.server --data-dir ./preview-data --port 19799
```

最后一个命令使用独立数据目录和端口，浏览器打开 `http://127.0.0.1:19799`。不要把第二个采集器指向正式数据目录。修改前端后重新运行 `build_frontend.py`，重启预览服务再刷新页面；服务会在启动时更新静态资源清单及 CSP 哈希。

`npm run dev` 只启动前端开发服务器，当前不代理 Python API；完整功能验证使用上面的静态构建预览。`build_frontend.py --install` 会先执行 `npm ci`。依赖版本通过 `package-lock.json` 锁定，shadcn 组件源码直接纳入项目。

桌面构建沿用已配置 PyInstaller、PyYAML、Markdown 的 Python 环境：

```sh
python3 build_macos.py --work-dir ./build-work --output ./release
```

默认先构建文档和前端，然后封装原生应用。`--skip-frontend` 仅用于已完成文档及前端验证的重复封装。输出目录中包含 `.app`，可用 `hdiutil create` 制作 DMG。0.2.0 使用 macOS 13.3+ 的系统声明，现代 WebKit 为 Tailwind 4 提供所需 CSS 能力。

升级前停止后台服务并退出旧应用，再替换应用。数据目录、身份密钥、清理策略和订阅覆盖继续沿用，无数据库迁移。旧版安装包可回退使用同一数据目录。
