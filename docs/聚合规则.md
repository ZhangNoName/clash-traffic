# 聚合规则

本说明适用于 Clash 流量簿 0.1.4。所有合计都是已经采集到的代理传输字节，不能当作机场账单。切换聚合方式不改写原始记录。

## 推荐用法

平时使用「合并 ChatGPT / Codex」和明细「汇总」。核对重复应用时，点击行末「来源」；希望完全分开看时，选择「应用分别统计」及「按来源」。三项偏好（图表类型、应用归并、明细方式）保存在本机，重启继续生效。网址中的明确选项优先于保存的偏好。

## 为什么会有两个 Chrome

同一个应用可以使用不同订阅、实际节点和代理链。旧版把代理链分别列成行，却没有直接展示差异，因此看起来一模一样。

新版汇总维度是：**应用身份 × 有效订阅 × 节点身份**。例如同一 Chrome、同一订阅和同一节点，分别走 `Google → Proxies → 节点` 与 `Final → Proxies → 节点`，现在合为一行，点击「来源 · 2」查看两条来源。

同名但不同身份的节点仍分开。节点编号来自活动配置、实际节点身份与 Provider 信息；配置上下文变化可能形成新编号，即使名称相同也不会贸然合并。同名应用的身份也可能不同，界面显示编号前 8 位，来源弹窗显示完整编号。

应用身份优先从进程路径所属 `.app` 的 Bundle ID 获取，否则使用应用包路径或进程信息生成本机 HMAC 编号。名称只是标签。历史库没有保存原始进程路径和 Bundle ID，因此不能事后还原两个历史编号究竟来自哪个安装路径。编号用于区分，不代表安全身份认证。

## ChatGPT 和 Codex 怎么合并

| 已记录的应用名称 | 合并模式 | 分别统计模式 |
| --- | --- | --- |
| ChatGPT | ChatGPT / Codex | 按原始应用编号分别显示 |
| codex / Codex | ChatGPT / Codex | 按原始应用编号分别显示 |
| ChatGPT Computer Use | ChatGPT / Codex | 按原始应用编号分别显示 |
| Chrome / Google Chrome | 保持原应用 | 保持原应用 |
| chrome-headless-shell | 保持原应用 | 保持原应用 |
| 其他名称 | 保持原应用 | 保持原应用 |

匹配规则是去掉名称两端空格、忽略大小写后的**完全匹配**，不做关键词包含匹配。`ChatGPT Helper` 这样的独立历史名称不会因为包含 ChatGPT 被自动合并；如果采集时已识别为 ChatGPT 所属应用，保存的名称是 ChatGPT，则按该记录归并。

这是一个方便查看的应用组合，不表示 ChatGPT、Codex 和 Computer Use 是同一产品或同一进程，也不能推断请求由哪个会话发起。浏览器访问 ChatGPT 网站仍算浏览器；当前系统不保存访问域名，不按网站划分流量。

组合模式中，排行和应用筛选使用相同的组合身份 `family:openai`。切换合并方式会清除应用筛选，保留日期、订阅和节点筛选，避免旧筛选造成误解。当前没有自定义组合编辑器。

## 汇总、来源和连接有什么区别

| 查看方式 | 分组维度 | 用途 |
| --- | --- | --- |
| 汇总 | 显示应用身份、有效订阅、节点身份 | 日常看用量，折叠代理链差异 |
| 按来源 | 原始应用编号、有效订阅、节点编号、代理链、归属依据 | 核对原始应用与路由差异 |
| 来源弹窗 | 所选应用和节点在当前范围内的原始来源 | 查看完整编号、链路、上传、下载、首末记录分钟 |

「来源数」是不同来源组合数量，不是连接数、进程数或请求数。同一组合里的不同分钟会累加。来源弹窗中的时间是当前查询范围内第一条和最后一条记录所在分钟，不是连续在线时间。按来源模式下点击来源，会查看该原始应用、订阅、节点下的所有链路。

每行总量 = 上传 + 下载。相同筛选下，汇总与按来源的总量相同；组合前后总量相同。排行只显示前 50 名，不保证把整个排行相加等于全部流量；明细可翻页，导出包含所有匹配行。

手动指定订阅作用于节点身份，历史与后续查询都会使用覆盖后的订阅；撤销覆盖即可恢复原始归属。归属调整不改变流量字节。

## 日历怎么读

「本月」覆盖当月 1 日至下月 1 日，「本年」覆盖当年 1 月 1 日至次年 1 月 1 日，结束时间不含。自定义范围达到 28 个日期时也展示日历。全部时间按北京时间计算；自定义首尾日期可能只有部分时段。

每个日期的颜色代表该日当前筛选下的**已记录上传 + 下载**。阈值固定，跨月可直接比较。界面 KB、MB、GB 按 1024 换算。

| 颜色等级 | 日流量范围 |
| --- | --- |
| 最浅灰绿 | 0，且有采集覆盖 |
| 浅绿 | 大于 0、小于 10 MB |
| 中浅绿 | 大于等于 10 MB、小于 100 MB |
| 中绿 | 大于等于 100 MB、小于 1 GB |
| 深绿 | 大于等于 1 GB |
| 灰色斜纹 | 没有覆盖记录，也没有匹配流量，不能判为零用量 |
| 淡色禁用 | 未来日期 |

`◦` 表示采集覆盖少于该日所选且已经过去时段的 98%。采集覆盖是全局记录器工作时间，不是某个应用在线时间，更不是字节完整率。即使覆盖很高，快照采样仍可能遗漏极短连接和断开前末尾流量。只有流量却没有覆盖信息的历史也标为部分记录。

鼠标停留或键盘聚焦日期，可阅读用量详情；点击日期切换到当天的按小时趋势。对于自定义范围，点击日期会查看完整当天，并在顶部显示新的范围。

## 柱状图和折线图

柱状图把下载和上传堆叠，柱高表示总量。折线图分别显示下载、上传两条线，不堆叠，读值使用相同纵轴；点上方不会再次加上另一条线的流量。无覆盖且无流量的时段会断线，未来时段不绘制，避免用连线猜测缺失数据。

粒度可选分钟、15 分钟、小时、天；单次最多 400 个时段。点击时段可读上传、下载并继续查看更细的时段。日历始终按天聚合，不随趋势粒度改变。

## 导出与数据保留

CSV 沿用当前日期、应用、节点、订阅筛选，以及应用归并和明细方式。除名称和字节外，还包含应用编号、节点编号、来源数、首末记录分钟和聚合模式。汇总模式不把多条链路拼成一个字符串，需核对链路时先选「按来源」再导出。

偏好与原始分钟记录分开存放；切换显示不迁移或重写历史。只有明确清理或自动保留策略才会删除历史。详见 [使用文档](使用文档.md)、[运行文档](运行文档.md) 和 [系统说明](系统说明.md)。
